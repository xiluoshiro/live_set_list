# 手工 SQL 的业务与交付约束

## 业务身份

只有正式更名新增名称历史版本，真实搬迁新建 Venue。所在地、地址、坐标与时区补录或纠错不产生版本；并发令牌和审计记录不作为业务版本，也不使稳定地图关联自动失效。

## SQL 格式与事务

- 直接执行的文件使用纯 SQL，明确 BEGIN 与 COMMIT，不含 psql 元命令；演练版本须单独标识。
- 文件适配真实执行器，执行器遇错停止；失败时整笔事务回滚，不产生部分写入。
- 按目标身份、所需结构及预期业务值检查冲突，不要求另一环境的 Flyway 执行历史、账号、时间或整表指纹一致。
- 保护非目标资料时，在同一事务内比较写入前后；支持幂等重试或明确拒绝重复状态。
- 只写目标字段及必要审计，不修改无关修订号、核验时间或 Live 排期。

## 验证与文件维护

使用最终 SQL 原文件验证提交、重复执行策略及冲突回滚。独立回填与应用代码分开存放，检查范围遵守目录规则；历史 SQL 的适用结构与当前生成器应明确区分。

## 执行边界

本地、测试库与远端是独立执行目标。文件修改不授权数据库执行，也不能把一个环境的结果当作另一环境的状态。
