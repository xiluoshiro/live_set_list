# Live 更新需求（已完成）

## 文档定位

状态：已完成并归档。当前接口字段与行为以代码、OpenAPI 和 [API 补充说明](../../api.md) 为准。

本文定义控制台更新既有 Live 基础资料的产品需求，不规定接口或组件实现。实现方式见 [Live 更新实现设计](../completed-design/live-update.md)。

## 目标

- `editor+` 可以在控制台按 Live ID 或标题找到任意既有 Live。
- 选择 Live 后回填与新增 Live 相同的基础字段，并在同一份表单中修改。
- 更新前明确展示发生变化的字段，避免误覆盖。
- 更新只修改 `live_attrs` 的可编辑基础资料，不修改 Setlist、巡演、活动组或收藏关系。

## 可编辑字段

- 日期、标题、Live 类型与 URL。
- 开场时间、开演时间和时区。
- Venue。
- 默认 Band。
- 活动类型的出演成员。

`live_id` 与 `is_internal` 不可编辑。

## 交互规则

- 控制台分别提供“新增Live”和“Live管理”页签：前者只负责录入，后者只负责查询和编辑。
- 两个页签复用同一套 Live 字段、Venue 和默认 Band 控件，但不共享候选工具栏、提交语义和成功记录。
- 编辑候选必须包含有无 Setlist 的全部 Live，并支持按 ID 或标题查询、类型筛选和分页。
- 编辑状态下，“恢复原值”撤销当前草稿；没有实际变化时不得提交。
- 切换 Live、切换到新建状态或离开当前编辑上下文时，如果存在未保存修改，需要先确认放弃。
- 保存前确认框只展示变化字段的原值和新值。
- 更新成功后继续停留在该 Live 的编辑状态，并以服务端响应作为新的原始值。
- 更新成功信息作为已保存结果；表单下方只在存在未保存修改时显示警告，干净状态不重复提示。
- Live、巡演和活动组的“新建”入口使用一致的强调样式；编辑选择器与 Venue/Band 控件使用一致的高度和字体。
- 新建 Live 提供“新增后清空录入数据”选项，默认开启；开启时成功后清空 Live 草稿、Venue 查询和 Venue 选择，关闭时保留这些数据以便连续录入。
- 提交后清空不影响成功记录，也不重置已有 Live 的关键词、类型筛选和分页上下文。

## 业务规则

- 非活动类型不得保存出演成员；活动切换为其他类型时清空出演成员。
- 移除默认 Band 时同步移除该 Band 的出演成员。
- 全员仍保存完整成员名单，`mode=full|partial` 继续由服务端计算。
- 有 Setlist 的 Live 仍可更新默认 Band，但公开端仍以实际 Setlist 乐队为准。
- 更新日期可能改变巡演或活动组内的展示顺序，但不得改变显式关联关系。

## 验收标准

1. 可以查询并加载任意 Live 的完整可编辑资料。
2. 修改并确认后，公开列表和详情能够读取新值。
3. 活动出演成员遵守活动专用、默认 Band 从属和完整名单规则。
4. Setlist、巡演、活动组与收藏关系在更新后保持不变。
5. 无变化不可提交，未保存草稿不会在无提示的情况下被覆盖。
6. 更新操作写入 `live_update` 审计日志。
