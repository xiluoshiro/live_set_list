# 专辑页面链接与多封面实现方案

本文细化[歌曲资料与专辑需求](../product/song-details-and-albums.md)中的专辑链接、多封面和默认封面规则。应用已改用 `album_url` / `cover_urls`，旧 `cover_path` 仅暂留数据库。

## 1. 范围与业务规则

管理员手动维护专辑页面 URL 和封面数组，每张封面保存 URL 与选填名称。图片由浏览器直接从外部地址加载，歌曲通过收录关系复用专辑封面。

| 字段 | API 类型 | 数据库类型 | 规则 |
| --- | --- | --- | --- |
| `album_url` | `string \| null` | `text NULL` | 专辑公告或平台详情页；尚未补录时允许为空，输入空白归一为 `null` |
| `cover_urls` | `{ url: string, name: string }[]` | `jsonb NOT NULL DEFAULT '[]'::jsonb` | 有序封面数组；名称可为空字符串，没有封面时为 `[]`，第一项为默认封面 |

- 新增、移除、调整顺序和设为默认都修改同一个数组；不增加默认封面 ID、默认下标或图片资源表。
- “设为默认”把该封面（URL 与名称）移到第一位，其余封面的相对顺序保持不变。
- 删除第一项后，新第一项自然成为默认；删除全部图片后保存空数组。
- 访客切换封面只改变当前页面状态，不写数据库，不改变默认值。
- 同一专辑的普通盘、限定盘等图片可以放在同一数组并填写名称；名称不绑定碟号或发行版子项。
- V42 起歌曲版本也保存独立 `cover_urls`；歌曲组不另存封面，使用默认版本的最终展示图。不同收录专辑仍各自保有图片数组。

本期不包含页面解析、Spotify/网易云接口接入、图片上传、文件代理、图床、定时抓取或批量补录现有专辑链接。

## 3. 存储与兼容边界

`albums.album_url` 为可空文本，`cover_urls` 为有序 JSONB 对象数组，默认 `[]`。数据库约束最多 20 项，URL 与名称均为字符串，名称最多 255 字；URL 格式、空白和重复值由请求模型校验。

数组顺序决定默认封面，不添加图片表、默认下标或独立默认封面 ID。运行角色沿用专辑的读取与管理写入权限，普通用户写角色没有资料维护权限。

应用只读写 `album_url` 和 `cover_urls`，不从旧 `cover_path` 回退取图。旧回填文件须按[回填说明](../../backfill/song-catalog-2026-09-26/README.md)匹配数据库结构，不能为历史文件永久保留运行兼容逻辑。

## 4. 请求校验、事务与 API

### 4.1 URL 与数组校验

- 两类 URL 都只接受有效的绝对 HTTPS 地址，拒绝用户名密码、控制字符、协议相对地址、本机文件路径、`data:` 和 `javascript:` 等协议。
- 每个 URL 最长 2048 字符；数组最多 20 项。去除首尾空白后进行验证，不重写路径、查询参数或来源页面的 fragment。
- `album_url` 的空白输入转换为 `null`；封面数组内的空字符串、NULL、重复 URL 返回 422，错误能定位到对应项。
- 数组省略与空数组按写入语义处理，显式 `cover_urls: null` 返回 422。
- 名称选填，最多 255 字，首尾空白被修剪；旧字符串输入转换为未命名对象，所有响应返回 `{ url, name }`。仅修改名称也参与变更确认、revision、审计和缓存失效。编辑器忽略完全空白行，但仅填名称未填 URL 时阻止提交。
- 不以 `.jpg` 等扩展名作为必要条件，支持没有文件扩展名的 CDN 地址。
- 服务端只校验 URL 数据，不访问地址、不执行 HEAD 检测，也不根据远端是否暂时可用阻止保存。前台预览失败不等于 URL 格式非法。
- 手工外链不限制为某几个图片供应商；本期没有服务端抓取入口，因此不引入平台解析器或抓取域名配置。

### 4.2 复用现有接口

| 接口 | 行为 |
| --- | --- |
| `POST /api/console/albums` | 接收两字段；省略时分别使用 `null` 和 `[]` |
| `PUT /api/console/albums/{id}` | 继续要求 `expected_revision`；未提供的新字段保留原值，显式 `null` 或 `[]` 分别清空页面链接或封面数组 |
| `PUT /api/console/albums/{id}/tracks` | 仅修改曲目，保留页面链接和封面数组，包括默认顺序 |
| `GET /api/console/albums`、`GET /api/console/albums/{id}` | 返回两字段，便于管理草稿完整回填 |
| `GET /api/albums/{id}` | 返回相同字段及完整曲目 |
| `GET /api/songs/{id}`、`GET /api/song-groups/{id}` | 嵌套的专辑摘要返回两字段，保持已有按专辑去重的语义 |

示意资料片段：

```json
{
  "album_url": "https://bang-dream.com/discographies/3302/",
  "cover_urls": [
    { "url": "https://images.example.test/album-standard.jpg", "name": "通常盤" },
    { "url": "https://images.example.test/album-limited.jpg", "name": "限定盤" }
  ]
}
```

管理表单每次保存明确提交两个字段。后端区分更新时的“未提供”和“显式清空”，并在取得专辑修订锁后确定最终值，避免元数据更新误清空图片。

所有写入继续沿用 editor 权限、session、CSRF、专辑 revision 和审计事务。过期 revision 返回 409；失败时原链接、数组、曲目和 revision 保持不变，前端保留草稿。

API 和数据库 JSONB 数组均以第 0 项表示默认封面。不得通过排序、集合转换或按 URL 字典序重排数组。

成功保存继续调用现有 `songCatalogWrite`，复用歌曲资料缓存清理及跨标签页变更事件。图片切换不调用保存接口，也不触发资料缓存失效。

## 5. 后台管理交互

沿用专辑管理现有的表单、表格、按钮、保存确认和放弃草稿流程：

1. 在资料字段中加入“专辑页面”输入框，替换原“封面文件”单值输入。
2. “封面”区域使用现有 Console 表格样式，每行展示小图预览、URL 输入和操作。
3. 提供“添加封面”“上移”“下移”“设为默认”“移除”。首项的默认操作显示为不可操作的“默认”，避免额外说明段落。
4. 新增行在草稿中可以暂时为空，但保存前必须补全或移除；不静默过滤空行或重复项。
5. 设为默认、排序和移除仅修改草稿，统一走原有保存确认。默认封面不另发单独的写请求。
6. 确认表继续复用 `UpdateDiffTable`，分别展示“专辑页面”“封面”前后值；封面值按顺序编号，并标明首项为默认，使仅调整默认值的修改也清楚可见。
7. 保存中和确认中沿用既有锁定行为；恢复原值、切换专辑、新建专辑、取消确认和 409 错误均保留原有草稿规则。

管理 URL 使用 textarea 或可收缩的输入单元格承载长地址，复用现有输入样式。新增的布局规则仅作用于封面区域，不改共享表格的列宽或全局输入样式。

## 6. 公共页面展示与切换

### 6.1 收录专辑卡片

- 卡片显示 `cover_urls[0]`，保留原有“点击专辑展开详情”的交互。
- 空数组时沿用文字展示，不增加空封面提示。
- 图片按完整内容等比显示，不裁切封面。加载失败不会隐藏专辑标题、发行信息或详情入口。

### 6.2 展开专辑详情

- 在既有展开区域显示封面，并在存在 `album_url` 时提供“专辑页面”外链；新标签页打开并使用 `noopener noreferrer`。
- 首次展开显示第一张。多图时用既有简洁按钮形式提供“上一张”“下一张”和当前位置，例如 `1 / 3`；首尾禁用对应方向，不自动轮播。
- 只有一张时不显示切换控件；空数组时省略图片区域。
- 切换封面不触发收起、跳转歌曲或重新请求专辑详情。控件放在现有专辑按钮外，避免按钮内嵌按钮。
- 切换专辑、切换歌曲版本或重新展开时回到默认图；新资料载入后若 URL 数组发生变化，也从第一张开始。
- 图片切换状态独立于歌曲演奏记录、分页和异步详情请求；继续保留现有请求代次校验，旧请求不能覆盖新选择。
- 加载失败时显示简短失败状态，仍允许切换其他封面或访问专辑页面；不自动修改默认顺序、不跳过失效 URL 写回数据库。
- 使用固定占位尺寸或比例、懒加载及描述图片内容的替代文本；窄屏下图片和切换按钮不得撑宽详情区域。

### 6.3 样式复用与视觉确认

后台封面行与现有专辑曲目排序表在角色、操作、状态和视觉结构上高度相似，直接复用 `console-admin-table`、`console-table-wrap` 及已有按钮样式。保存确认继续复用 `UpdateDiffTable`。

前台继续使用 `song-catalog` 的详情容器、分页按钮和主题变量；只补封面展示所需的局部布局。实现前在浏览器中确认现有页面，检查宽屏、390px 窄屏和深浅色主题。

## 8. 验证范围与完成标准

### 8.1 后端与真实数据库

- 新专辑省略字段得到 `null` / `[]`；显式单图、多图数组按提交顺序完整往返。
- 调整第一项改变默认封面；清空、移除首项、数组上限和 URL 上限按契约处理。
- 拒绝非 HTTPS、无效 URL、空元素、NULL 元素和去空白后的重复项；允许不带扩展名的有效 CDN URL。
- 只改其他资料且未提供新字段时保留链接；仅修改曲目后页面链接、封面内容和顺序不变。
- 过期 revision、越权或 CSRF 失败不产生部分更新；普通用户账号不能写专辑资料。
- 通过管理详情、公共专辑详情、歌曲详情和歌曲组详情读取一致数据；同一专辑的多次收录不会产生重复封面条目或改变演奏次数。
- V40 增量迁移保留已有专辑 ID、曲目关系、revision、旧列读取能力和对象所有权；旧字段含非空数据时明确停止。
- 数据库数组约束通过真实 SQL 验证，不用预设 mock 结果代替存储顺序和约束检查。

### 8.2 前端行为

- 添加、排序、设为默认、移除、恢复、取消及保存失败均验证用户可见结果和实际提交数组。
- 仅调整默认图也会产生待保存状态，并出现在确认差异中。
- 卡片使用首图；展开详情默认首图；上一张/下一张正确切换，单图不出现无意义的切换控件。
- 图片失败、切换专辑、切换版本和数组更新后仍可操作，选择状态不会串到另一张专辑。
- 点击图片切换控件不触发专辑收起或歌曲跳转，且不会发送写请求。
- 资料保存后公共详情刷新，新顺序在同页与跨标签页可见。

自动测试使用受控 URL 和可模拟的图片加载事件，不依赖官网、Spotify 或网易云在线状态。相关测试补充简洁“测试点”注释；不以 CSS 类名、像素值或源码关键字断言代替业务和视觉证据。

### 8.3 执行命令与本地浏览器

前后端共同变更按根目录检查规则执行：

```powershell
python scripts/run_checks.py functional
```

数据库集成场景保持串行。视觉与交互检查使用隔离测试库和既有测试管理员，覆盖宽窄屏及深浅色主题；自动化后台服务不使用 Uvicorn reload。

本地浏览器至少检查空数组、单图、多图、首图失败、长 URL、长专辑标题和窄屏布局。可选真实外链冒烟仅验证当时的网络可用性，不把第三方服务可用性设为自动测试成功条件。
