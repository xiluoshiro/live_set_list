# 首页 Live 日历改造设计

## 1. 文档定位

本文定义 LiveSetList 首页公共发现区的改造方案：用可交互的“Live 日历”替换当前“最近收录”列表，并从首屏移除“个人与贡献”区域。

本文是实现设计，覆盖产品取舍、信息架构、视觉与交互、接口契约、状态处理、响应式行为和验收条件。长期产品方向仍以[社区 Live 数据库首页与个人工作台需求](../product/homepage-community-database.md)为准；本文只修正个人能力在首页首屏中的位置，不取消收藏、登录或编辑贡献能力。

- [Live 日历 Stage Ledger 风格预览 v2](previews/home-live-calendar-v2/index.html)

## 2. 结论摘要

本轮采用以下方案：

1. 首页保留搜索、四项数据概览和“最新 Live 日期”。
2. 删除“最近收录”标题及其六行 Live 列表，替换为整行宽度的“Live 日历”。
3. 日历按 `live_date` 表达演出时间轴，不表达资料录入或编辑时间。
4. 有 Live 的日期在单元格底部显示状态色轨，同时显示“n 场”；颜色不是唯一信息载体。
5. 选中日期后，在同一区域展示当天 Live 的开始时间、标题、Band 图标和文字状态，并可进入详情。
6. 从首页 DOM 中完整删除“个人与贡献”区，不为匿名用户、登录用户或编辑用户保留首屏占位。
7. 登录仍在全局顶部栏，收藏仍在演出资料范围切换中，`editor+` 的控制台仍由角色感知导航承接。

设计参数：

| 参数 | 值 | 解释 |
|---|---:|---|
| `DESIGN_VARIANCE` | 5 | 新增日历工作区，但继续使用现有首页和主题系统的视觉语言 |
| `MOTION_INTENSITY` | 2 | 只做月份、选择态和加载状态反馈，不加入装饰动画 |
| `VISUAL_DENSITY` | 6 | 同屏保留整月概览和选中日详情，移动端改为纵向阅读 |

## 3. 问题与现状依据

### 3.1 “最近收录”语义不成立

当前首页在 `frontend/src/App.tsx` 中调用 `getLives(1, 15)`，再在 `HomeDashboard` 中展示前六项。后端 `GET /api/lives` 的默认排序为：

```sql
ORDER BY l.live_date DESC, l.id DESC
```

因此该区域实际展示“演出日期最晚的 Live”，并不是“最近新增”或“最近编辑”。当前数据也没有通过这个接口返回可证明收录顺序的 `created_at` 或 `updated_at`。

改造后直接使用“Live 日历”，让标题、排序依据和用户看到的日期保持一致。如果未来需要“最近编辑”，应以独立审计时间和独立接口实现，不能复用日历或 `live_date` 冒充。

### 3.2 当前列表不足以支撑月历

当前首页只读取列表第一页的 15 条数据。用这 15 条在前端拼月历会产生以下错误：

- 当月超过 15 场时会漏项。
- 列表第一页可能跨月，无法判断某一天真的没有 Live，还是数据未取到。
- 切换到过去月份时需要不断猜测分页位置。
- 取消、延期等少量异常状态可能因分页被漏掉。

生产实现必须按完整自然月查询，日期条件要在 SQL 查询和聚合之前生效。

### 3.3 现有状态系统可以直接复用

项目已有统一的公开状态语义和主题令牌：

| 状态来源 | 展示文案 | 色调令牌 |
|---|---|---|
| `scheduled + past` | 已结束 | `past` |
| `scheduled + upcoming` | 待举行 | `upcoming` |
| `scheduled + today` | 进行中 | `today` |
| `postponed` | 延期，并保留日期阶段辅助信息 | `postponed` |
| `cancelled` | 已取消 | `cancelled` |

日历不得建立第二套颜色表。它应继续使用 `getLiveStatusPresentation` 对应的 `--live-status-*-bg/text` 令牌。Band 颜色只表示 Band 身份，不进入日期状态色轨。

## 4. 参照网站观察与取舍

以下观察用于提炼结构，不复制其他站点的品牌视觉：

| 参照 | 可取之处 | 不直接照搬的部分 | 对本方案的影响 |
|---|---|---|---|
| [setlist.fm](https://www.setlist.fm/) | 首页明确分开 Upcoming Events 与 Recent Edits | 两组长列表会挤占本项目较窄的首页 | “演出日期”和“资料编辑时间”必须分开命名；本轮只做日期浏览 |
| [Concert Archives](https://www.concertarchives.org/) | Upcoming、Happening、Past 是稳定的时间阶段 | 大型全球演出流和购票导向不适合本资料库 | 继续沿用既有状态体系，不另造“新收录”状态 |
| [Bandsintown](https://www.bandsintown.com/) | Today、This Week、This Month、Select Dates 先限定时间，再浏览条目 | 地理位置、推荐和票务不是本项目目标 | 月份是日历的主导航单位，选中日后再读详细条目 |
| [Resident Advisor](https://ra.co/events) | 日期筛选与按日分组的事件列表相互配合 | 强类型、流派与城市筛选会使首屏过重 | 月视图负责定位，右侧或下方列表负责阅读，不把标题塞进日期格 |

共同结论：日期控件适合回答“哪天有演出”，列表适合回答“这一天是什么演出”。两者应该联动，而不是让日历格同时承担完整详情。

## 5. 产品目标与非目标

### 5.1 目标

1. 用户无需搜索即可看出本月哪些日期有 Live。
2. 用户可以区分已结束、待举行、进行中、延期和已取消。
3. 用户可以在一次选择后查看当天所有 Live，并进入详情。
4. 首页继续像资料库入口，而不是营销落地页或个人工作台。
5. 320 CSS px 到桌面宽度均不出现页面级横向滚动。
6. 浅色、深色、键盘和触控场景使用同一信息结构。

### 5.2 非目标

本轮不负责：

- 展示真实的最近新增、最近编辑或贡献动态。
- 在日历中加入收藏、购票、签到、提醒或个人推荐。
- 在日期格内展示完整 Live 标题、场地或 Tour。
- 按 Band 颜色染色日期；状态和 Band 是两套不同语义。
- 一次性实现周视图、年视图、日期范围筛选或日历订阅。
- 删除收藏、登录、用户菜单或控制台能力。

## 7. “个人与贡献”首屏取舍

### 7.1 删除理由

当前区域在三类用户下都没有足够的首屏价值：

- 匿名用户只看到登录引导，与顶部栏登录入口重复。
- 普通登录用户只看到收藏数量和入口；收藏已经属于演出资料的核心浏览范围，不需要再占一个首页栏目。
- `editor+` 只多一个控制台入口；角色感知导航能更稳定地承接该能力。

首页最主要的公开任务是查询和发现资料。日历同时提供信息密度、时间定位和详情下钻，优先级高于重复的身份入口。

### 7.2 删除后的能力去向

| 能力 | 入口 |
|---|---|
| 登录 | 全局顶部栏和需要登录时的就地引导 |
| 我的收藏 | 演出资料页的“仅收藏”范围切换或用户菜单 |
| 控制台 | `editor+` 的角色感知导航 |
| 关于与反馈 | 首页底部轻量入口，继续保留 |

未来只有当个人区能提供收藏更新、关注动态、最近查看或贡献反馈等真正的连续使用价值时，才重新评估独立个人首页或首屏以下模块。不能仅因用户已登录就恢复一个空泛卡片。

## 8. 日历布局与视觉规范

### 8.1 桌面

- 日历区占首页内容宽度的整行，不再使用“最近收录 + 个人与贡献”的双栏结构。
- 区块标题左侧为“Live 日历”和一句使用说明，右侧为上个月、月份标题、下个月、回到本月。
- 图例位于标题与内容之间，使用细色轨加文字状态。
- 工作区建议使用约 `1.28fr / 0.72fr` 两列：左侧月历，右侧选中日详情。
- 两列之间只使用一条轻分隔线，不把每个日期或每场 Live 包成厚重卡片。
- 在 1440 x 900 的常见桌面视口中，应能看到搜索、概览、月历主体和选中日首批内容。

### 8.2 移动端

- 小于等于 760px 时改为单列：标题、月份导航、图例、月历、选中日详情。
- 月份导航第一行保留上个月、月份、下个月，“回到本月”单独换行。
- 日期格维持 7 列，不改成横向滚动列表。
- 390px 下日格最小高度建议 47-51px；“n 场”置于日期数字下方。
- 选中日详情放在月历下方，以顶部边线区分。
- 320px 下 Live 状态换到标题下方，标题允许合理截断，但核心状态和开始时间不能被裁掉。

### 8.3 状态色轨

每个有 Live 的日期格底部显示一条状态轨：

- 轨道按当天出现的“不同状态色调”分段，不按 Live 数量机械重复。
- 同一状态有多场 Live 时只占一段；总场次由“n 场”表达。
- 最多存在 `past`、`upcoming`、`today`、`postponed`、`cancelled` 五种分段，不得因条目过多丢失某一种异常状态。
- 分段顺序固定为 `cancelled -> postponed -> today -> upcoming -> past`，让异常和当前状态优先出现。
- `postponed` 使用间断纹理，`cancelled` 使用斜纹；其余使用实线。这样在低饱和或色觉差异场景下仍可区分。
- 选中态由边框和背景表达，不使用状态色代替选中态。
- 今天由日期数字外框和 `aria-current="date"` 表达，不把所有今天的 Live 强行改成同一种持久状态。

静态预览以最多三条事件色段演示视觉方向。生产实现必须采用上述“状态去重”规则，修正原型可能遗漏第四条及以后状态的问题。

## 9. 交互规则

### 9.1 初始月份与默认选中日

- 初次进入首页时展示当前自然月。
- “当前月”以客户端当前日期确定；Live 的 `date_phase` 仍由后端按该 Live 的 UTC offset 计算，前端不得自行改写。
- 当前月中如果今天有 Live，默认选中今天。
- 否则选中今天之后最近一个有 Live 的日期。
- 若本月没有未来 Live，则选中本月最近一个已过去且有 Live 的日期。
- 整月没有 Live 时：当前月选中今天，其他月份选中 1 日，并显示月级空状态。

### 9.2 月份导航

- “上个月”和“下个月”每次移动一个自然月并请求该月完整数据。
- “回到本月”返回当前自然月；已经位于本月时可以禁用或保持无副作用。
- 切换月份后按默认选中规则重置选中日，不延续无效的日号。
- 月份标题通过礼貌级 `aria-live` 通知变化，不抢走月份按钮焦点。
- 允许浏览没有 Live 的月份，不依赖静态的可用月份白名单。

### 9.3 日期选择与详情

日期格显示：

- 两位或等宽日期数字。
- 当天 Live 总数。
- 聚合后的状态色轨。

选中日详情显示：

- 月、日、星期和“n 场 Live”。
- 每场 Live 的开始时间；缺失时显示“时间未定”。
- Live 标题。
- Band 图标；图标使用现有 `BandIconsCell` 语义和资源。
- 文字状态，使用现有 `LiveStatusMeta` 或同一 presentation helper。
- 点击整行进入 Live 详情。

同日排序规则为：`start_time ASC NULLS LAST, live_id ASC`。不得按标题或 Band 随机重排。

### 9.4 键盘与可访问性

- 月历使用 `role="grid"`，星期使用 `columnheader`，日期使用可选择的 `gridcell` 或其内按钮。
- 只让当前漫游焦点日期进入 Tab 序列；方向键按一天或一周移动，Enter / Space 选择。
- 空白补位格不获取焦点。
- 今天使用 `aria-current="date"`，选中日使用 `aria-selected="true"` 或等价的单一选择语义。
- 日期的可访问名称至少包含日期、Live 总数和出现的状态及数量，例如“8 月 29 日，4 场 Live，待举行 3，已取消 1”。
- 色轨设置为装饰性；用户不依赖颜色也能从计数、可访问名称和右侧文字状态获得信息。
- 所有按钮保留现有全局可见焦点样式，触控目标不小于现有控件标准。

## 10. 数据与接口设计

### 10.1 新增接口

建议新增公共只读接口：

```http
GET /api/catalog/calendar?month=2026-08
```

`month` 使用 `YYYY-MM`，非法格式由 FastAPI 参数校验返回 `422`。接口不要求登录，不读取收藏状态。

建议响应：

```json
{
  "month": "2026-08",
  "items": [
    {
      "live_id": 123,
      "live_date": "2026-08-03",
      "live_title": "MyGO!!!!! 8th LIVE",
      "start_time": "18:00:00+09:00",
      "bands": [8],
      "event_status": "scheduled",
      "date_phase": "today",
      "was_rescheduled": false
    }
  ]
}
```

新增 schema 建议命名为 `CatalogCalendarLiveItem` 和 `CatalogCalendarResponse`。日历项目只返回渲染所需字段，不复制 Tour、Performance Group、URL 或收藏字段。

### 10.2 查询口径

后端先将月份转换为左闭右开的日期范围：

```sql
WHERE l.live_date >= :month_start
  AND l.live_date < :next_month_start
```

约束：

- 日期过滤必须在 Band 聚合、排序和结果构建之前生效。
- 返回该月全部 Live，不复用 `page=1&page_size=15`，不做前端补分页。
- 已取消和延期 Live 必须保留；日历本身就是公开状态的入口。
- Band ID 使用现有 effective band 口径并去重排序。
- 每条记录继续调用 `build_public_live_status`，`date_phase` 不由前端根据系统时区推断。
- 结果按 `live_date ASC, start_time ASC NULLS LAST, live_id ASC` 稳定排序。
- 查询使用公共只读连接，数据库错误和超时沿用 catalog 接口现有处理方式。

### 10.3 前端数据流

建议新增：

- `getCatalogCalendar(month)`：负责请求、响应类型和以月份为键的短期缓存。
- `HomeLiveCalendar`：持有月份导航、选中日和状态聚合的页面组件。
- `CalendarGrid`：负责日期格、键盘漫游和可访问名称。
- `CalendarDayDetail`：负责选中日的 Live 行与空状态。

`App.tsx` 不再用 `getLives(1, 15)` 作为首页数据源。`HomeDashboard` 删除以下仅服务旧“个人与贡献”或“最近收录”的 props：

- `isAuthenticated`
- `canUseConsoleFeatures`
- `favoriteCount`
- `recentRows`
- `onShowFavorites`
- `onShowConsole`
- `onLogin`

如果这些值仍被其他页面使用，只移除首页传递链，不删除全局能力。

## 11. 加载、错误与空状态

### 11.1 初次加载

- 搜索和数据概览独立加载，不因日历请求阻塞整个首页。
- 日历区保留标题与月份导航，内容区显示与最终高度接近的加载结构。
- 区域使用 `aria-busy="true"`，完成后更新选中日。

### 11.2 切月加载

- 月份标题立即更新，旧月数据不得伪装成新月份。
- 内容区进入局部加载状态；请求完成后一次性替换网格和详情。
- 快速连续切月时只接受最后一次请求的结果，避免旧响应覆盖新月份。

### 11.3 空月份

- 仍渲染完整月份网格。
- 标题下显示“本月暂无已收录 Live”，选中日详情显示无数据说明。
- 空月份不是错误，不引导用户登录或贡献。

### 11.4 请求失败

- 只在日历区显示“Live 日历加载失败”和重试按钮。
- 保留用户当前选择的月份。
- 不把错误解释为“本月没有 Live”，也不清空已成功加载的数据概览。

## 12. 与静态预览的关系

[静态预览](previews/home-live-calendar/index.html)用于确认以下方向：

- 删除“个人与贡献”后的整行日历构图。
- 月份导航、状态图例、日期选择和选中日详情的层级。
- 浅色 / 深色主题。
- 桌面双列和移动端单列。
- 日期计数、状态色轨、Band 图标和详情行的视觉密度。

预览不是数据契约：

- `preview.js` 中的数据是固定 fixture，不得复制到生产代码。
- 预览固定“今天”为 2026-08-03，生产实现必须使用真实当前日期。
- 预览只提供 2026-07 至 2026-09，生产实现允许连续切换自然月。
- 预览中的点击 toast 只是交互占位，生产实现进入真实 Live 详情或列表。
- 生产状态色轨按状态去重，不能沿用原型的 `events.slice(0, 3)`。

## 12.1 与 v2 预览及设计的实现差异记录

生产实现（`frontend/src/components/HomeLiveCalendar.tsx`、`CalendarGrid.tsx`、`CalendarDayDetail.tsx`、`styles/home-calendar.css`）与本文及 v2 预览的落地差异：

1. **视觉整体采用 v2 预览的 Stage Ledger 风格**：首页 hero、数据概览、最新 Live 日期、日历区与页脚全部按 v2 重做（hairline 分隔、4px 圆角、mono 元数据），不再保留旧的圆角卡片风格。
2. **数据概览的“已收录 Live”来自新字段**：后端 `GET /api/catalog/stats` 新增 `live_count`，替代被移除的 `getLives(1, 15)` 分页总数。
3. **日历格压缩**：工作区比例为 `1fr / 0.9fr`（日格约 85-90px）、日格高 44px、网格 gap 4px；分隔线经 `color-mix` 加深一档以适配浅色主题。
4. **详情行 Band 图标与标题同行**：最多渲染 2 个图标 + `+N` 溢出计数（mono），悬停 `title` 展示完整列表；图标不带衬底。
5. **详情行可访问名称**：整行按钮 `aria-label` 直接使用 Live 标题，键盘与测试均按标题定位。
6. **“查看全部 Live”按钮**位于选中日详情底部（`onShowAll` 跳转演出资料页），不再有首页“乐队浏览”链接（顶部导航保留）。
7. **`HomeDashboard` 删除** `isAuthenticated`、`canUseConsoleFeatures`、`favoriteCount`、`recentRows`、`onShowFavorites`、`onShowConsole`、`onLogin` 七个 props；`App.tsx` 不再请求 `getLives(1, 15)`，跨标签控制台变更通过 `liveDataRevision` 驱动日历重取当前月。
8. **缓存**：`getCatalogCalendar(month)` 使用以月份为键的 10 分钟 LRU 缓存，并入 `clearLiveDataCaches` 失效链路。
9. **键盘漫游**：方向键按天/周移动焦点、Enter 选择；今天用 `aria-current="date"`，选中用 `aria-pressed`，可访问名称包含日期、场次与各状态计数。

## 14. 测试与验收

### 14.1 后端自动化

- `month` 非法格式返回 `422`。
- 只返回指定自然月内的数据，月初和月末边界正确。
- 同日按开始时间排序，缺失时间排在最后，再按 `live_id` 稳定排序。
- 取消、延期、已改期和正常 Live 都保留正确公开状态。
- 同场多 Band 去重且顺序稳定。
- 空月份返回 `items: []`，不是 404。

### 14.2 前端行为测试

- 首页显示“Live 日历”，不再显示“最近收录”和“个人与贡献”。
- 匿名、登录和 `editor+` 三种身份都不恢复个人区占位。
- 初始月份和默认选中日符合规则。
- 切月只展示对应月份响应，过期请求不能覆盖新状态。
- 同日多场显示正确总数，色轨包含所有不同状态。
- 选中日期后展示全部 Live，并能进入对应详情。
- 空月、请求失败和重试行为相互区分。
- 键盘方向键移动、Enter / Space 选择及可访问名称正确。

## 15. 完成定义

7. 自动化测试和 `python scripts/run_checks.py functional` 全部通过。
