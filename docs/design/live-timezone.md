# 演出时区与访问者日期

## 时间录入

- 实体场馆和未公开类型场馆必须提供自身 IANA 时区；时区独立于地址、坐标和地区。
- 未选择场馆时，开场、开演必须均未公布。前端及后端均拒绝无场馆但有时间的输入。
- ONLINE 不保存场馆时区，演出使用固定 UTC 偏移；只有填写开场或开演时间时才需要偏移。
- 非 ONLINE 演出由后端根据场馆时区、演出日期和当地钟点计算偏移。夏令时不存在或重复的钟点均拒绝，不提供重复次数选择。
- `live_date` 保存公布的演出日期，`opening_time`、`start_time` 使用 `timetz` 保存当地钟点及计算后的偏移。两项时间可以独立未公布。
- 不保存演出的 IANA 快照、来源、来源修订、独立偏移分钟及重复次数；历史时间自身携带偏移。地区不保存时区。
- 普通资料编辑保留已有时间。日期、场馆或钟点发生变化时重新解析，不建立场馆修改后的批量重算机制。

## 日期与显示

- 请求携带访问者的 IANA 时区，后端统一计算访问者日期、日期状态及对应筛选和排序。无浏览器时区的调用采用 UTC，不写回业务数据。
- 已知开演时间时以开演瞬间确定访问者日期；只有开场时间时采用开场瞬间；两项都未公布时直接使用公布日期。
- 日历按访问者实际日期归月、归日，包含从相邻原始月份跨入的演出。
- “待举行／进行中／已结束”、控制台日期筛选与日历使用相同日期规则。
- 演出详情保留公告当地钟点及原有时区缩写格式。有场馆 IANA 时区时，后端按各项时间对应的瞬间生成缩写；无 IANA 时沿用固定偏移映射（如 `+09:00 → JST`），未收录偏移显示 `UTC±HH:MM`。未知时间显示“未公布”；日历仍显示访问者当地钟点。
- 排期历史使用历史场馆的 IANA 时区和历史演出时刻生成缩写；这些显示字段只在查询时计算，不落库。

## 数据迁移

- 先从唯一且已有的演出 IANA 记录补齐未公开场馆自身时区；冲突或缺失资料使迁移停止，不猜测时区。
- 保留所有已保存的演出日期及带偏移时间，再删除重复时区字段及地区时区。
- 新增版本化迁移，不修改已执行迁移。既有资料若违反无场馆不可有时间的规则，须先明确修正，不能静默清空。
