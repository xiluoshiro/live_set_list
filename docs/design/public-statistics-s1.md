# 公共统计 S1 实现设计

## 范围

本设计实现 [公共 Live 与收藏 Live 统计需求](../product/public-statistics.md) 的 S1。产品口径仍以需求文档为准；本文只记录接口、查询与页面落地方式。

## 接口

新增 `GET /api/catalog/statistics`：

- `scope=all|favorites`，默认 `all`；收藏范围由当前 session 确定用户，匿名请求返回 401。
- 可选 `year`、`live_type`、`band_id`，以及选择乐队后的排行 `limit`。
- 响应固定包含实际范围与筛选、概览、年份分布、Live 类型分布、高频歌曲、久未演唱歌曲。
- 全部与收藏仅在候选 Live CTE 的来源上不同，后续聚合共用同一实现。

`GET /api/catalog/stats` 继续服务首页轻量概览，不承载歌曲排行。

## 查询口径

1. 先按 scope、年份、类型和乐队得到候选 Live。
2. 有 setlist 时，Live 的有效乐队来自 `live_setlist.band_member`；完全没有 setlist 时回退到 `live_attrs.default_band_ids`。
3. 歌曲次数按 `band_member` 中的实际演唱乐队与歌曲共同分组，不使用歌曲原属乐队代替演唱者。
4. 未选择乐队时，每支乐队只返回内部排名第 1 的歌曲，并按 `band_id` 升序展示；选择乐队后返回该乐队按演唱次数排序的 Top N，避免单一乐队刷榜。
5. 高频歌曲同时返回出现 Live 数与 setlist 行数，默认按前者排序。
6. 久未演唱只在选定乐队后计算；歌曲至少需在候选集出现两场，并以该乐队候选 Live 的最近日期作为参照。
7. 概览中的歌曲数按 `(实际演唱乐队, song_id)` 去重，因此同一歌曲由多支乐队演唱时会分别计数。

## 页面

顶层导航新增“数据统计”。页面包含：

- 全部 Live / 收藏 Live 范围切换；匿名点击收藏范围复用现有登录框。
- 年份、乐队、Live 类型筛选，切换范围时保留筛选条件。
- 概览卡、年份条形分布、类型分布、高频歌曲、久未演唱。
- 歌曲条目可进入最近一次相关 Live 详情。
- Live 类型中文名称只由前端 `LIVE_TYPE_LABELS` 字典提供；统计接口返回稳定 code，`multi_act` 与控制台统一显示为“拼盘”。

前端不把 `MAX(live_date)` 描述为资料更新时间，统一使用“本站已收录”的样本口径。

## 当前边界

- S1 暂不提供歌曲逐年详情页、完整相关 Live 列表和可分享 URL；首批下钻落到最近相关 Live。
- 当前统计页是单次完整响应；尚未实现模块级独立失败与局部重试。
- 当前响应尚未包含独立统计计算时间，`latest_live_date` 只表示候选 Live 的最晚演出日期。
- 暂不增加缓存或物化视图；数据量增长后再依据真实慢查询决定。
- 从未演唱、回归间隔、开场/压轴/安可和 setlist 结构属于 S2。
