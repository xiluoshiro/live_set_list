# 场馆所在地与时区

## 职责

场馆维护名称身份、所在地区、门牌地址、成对 WGS84 坐标、自身 IANA 时区和地图平台关联。演出时间、访问者日期及 ONLINE 固定偏移的规则统一见 [演出时区与访问者日期](live-timezone.md)。

- 正式更名新增名称历史；真实搬迁新建场馆。资料补录及纠错不生成名称版本。
- 并发编辑使用内容状态令牌，修改记录由通用审计保存。主数据不批量重算既有演出时间。
- 新增页面字段与交互见 [新增场馆](../venue-create-form.md)。
- 地图点选、离线时区解析和地址建议见 [地图定位设计](venue-map-picker-and-resolution.md)。

## 地区

`geo_localities` 保存国家、一级行政区、城市和层级。地区只用于位置分类，不保存时区，不限制场馆自身时区。

国家层级不填行政区和城市；行政区层级必须填写行政区而不填城市；城市层级必须填写城市。同一国家下按层级及名称保持唯一性，允许先登记行政区而不补造城市。

## 场馆

| 字段 | 规则 |
| --- | --- |
| `locality_id` | 已公布地区，可空 |
| `address` | 实体场馆新增必填；未公开及 ONLINE 不保存 |
| `latitude` / `longitude` | 可空，成对填写，WGS84；纬度范围 ±90，经度范围 ±180 |
| `timezone_id` | 实体及未公开场馆必填 IANA；ONLINE 为空 |

时区不以坐标或公开门牌为前提。未公开场馆可以保存已公布地区及自身时区，但不推测具体位置。ONLINE 使用统一记录，各演出采用自身固定偏移。

地图解析给出的时区是填写建议；异常或失败保留用户草稿，不伪造坐标或解析结果。已确认的场馆时区用于后端录入演出时间。

## 地图关联

每个场馆在每个平台最多保存一条关联。链接必须通过对应地图平台的 HTTPS 白名单校验；地点 ID 或详情 URL 至少有一项。

有已确认关联时打开对应场馆详情；无关联但有坐标时打开坐标点；没有坐标时不显示精确场馆定位。资料修正不使已确认关联自动失效。

坐标不代表入口，不因坐标相同合并场馆。地图候选名称不自动覆盖场馆名称；用户确认后才保存。地图链接和位置资料编辑仍遵循状态令牌并发校验。
