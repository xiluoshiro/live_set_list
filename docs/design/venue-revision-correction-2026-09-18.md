# Venue 版本语义纠正（2026-09-18）

只有正式名称变化产生名称历史版本；真实搬迁创建新 Venue。所在地、地址、坐标与 IANA 时区允许补录和录错纠正，但不产生业务版本。

## 排查结果

- V30 将位置修订号默认设为 1；首次位置回填将 153 个实体 Venue 增至 2，Venue 32 的地区补录也增至 2。IANA 回填继续递增该值，错误地把资料补录当成业务版本。
- 日常位置保存将所有字段变化都视为位置修订；地区保存也传播修订至引用 Venue。
- 地图关联按位置修订判断有效性，导致地址、时区等纠错误使 POI 失效；Live 来源修订号继承了这些非业务版本。
- 正式更名已有 `venue_name_versions`；控制台和 API 只允许追加正式更名，已有名称文本纠错、迁移和回填仅通过 SQL。

## 修改方案

1. 地理接口移除业务修订号和地图自动过期联动。资料补录／纠错只保存当前事实与 before/after 审计；地图关联属于稳定 Venue，须明确修改／取消，不因其他字段纠错失效。
2. 防止旧表单覆盖新内容，使用当前已读数据的 SHA-256 状态令牌做并发检查。令牌按内容计算，不持久化、不递增、不形成历史版本；位置令牌覆盖当前 Venue、所在地及地图关联。名称版本仍是唯一业务版本。
3. Live 新写入不再记录地理来源修订号，IANA、偏移和排期历史语义保持不变。
4. 为避免改写已执行迁移，保留数据库旧列作为停用兼容字段：Venue 和地图位置修订列取默认 1；地区修订不再递增；Live 地理来源修订为空。应用读写不再以这些字段驱动业务。旧手工回填文件不作为后续操作模板。
5. [元数据纠正 SQL](../../backfill/2026-09-18-02__correct_initial_geography_revisions.sql) 清理旧修订元数据，保留 IANA、地址、坐标、名称版本、排期事实和旧审计。执行顺序、幂等与冲突规则见 [回填说明](venue-own-timezone-backfill-2026-09-18.md)。

## 回归约束

覆盖资料补录／多次纠错、无变更保存、旧请求拒绝、地图保存并发、地区纠错不写 Venue、地图保持有效、正式更名只追加名称版本、控制台不提供名称原地纠错、搬迁采用新 Venue、Live 新写入无来源修订。
